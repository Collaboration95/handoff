AGENTS EVERYWHERE HACKATHON — UPDATED CONTEXT
Last updated: 2026-09-12

EVENT
- OpenAI x AI Tinkerers "Agents Everywhere" hackathon in Singapore.
- One-day hackathon.
- Solo participation is allowed.
- Total build window is roughly 255 minutes (~4h15m).
- Personal implementation target: get the core demo stable within ~3 hours.
- Judging strongly rewards a sharp, working demo over a broad but incomplete product.

- Human approval / responsible action boundaries are valuable.

CURRENT PROJECT DIRECTION
Project: Handoff

Core idea:
"Meetings should not end with a list of action items. They should end with the actions already done."

Handoff is a realtime meeting participant that:
1. Listens to the ongoing meeting.
2. Maintains enough conversational context to resolve references such as:
   - "that issue"
   - "the fix"
   - "him"
   - "what we decided"
3. Lets users explicitly invoke it in natural speech.
4. Performs real actions in GitHub / Slack.
5. Gives spoken confirmation.
6. Shows a visible action trace in the meeting UI.
7. Can ask for lightweight confirmation before consequential actions.
8. Can optionally extend into one narrowly scoped finance workflow through the Airwallex Developer MCP sandbox.

LATEST IMPLEMENTATION STRATEGY
Prefer OpenAI technologies where they solve a real problem, because OpenAI is a hackathon partner, but do NOT force OpenAI components into places where simpler infrastructure already solves the problem better.

Use:
- LiveKit Meet for the video/audio meeting surface.
- LiveKit Agents for the agent participant.
- GPT-Live-1 for realtime full-duplex spoken interaction and interruption.
- OpenAI Responses / delegated reasoning for low-latency intent + tool selection.
- Thin direct GitHub and Slack functions for deterministic realtime side effects.
- Optional OpenAI Agents API for long-running/deep work only.
- Optional GPT-6 Astra for deep autonomous coding/repository tasks if API access is available.
- Optional GitHub MCP in the deep-work path where broad repository access is useful.
- Optional Airwallex Developer MCP in the sandbox for one payment-link action only.

DO NOT REBUILD SOLVED INFRASTRUCTURE
Do NOT spend hackathon time implementing:
- video calling
- WebRTC negotiation
- audio transport
- custom STT
- custom TTS
- recording
- custom interruption handling
- generic agent orchestration
- vector databases
- long-term memory
- production OAuth
- production payments infrastructure, cards, payouts, beneficiaries, or broad finance workflows
- contact-management systems
- broad multi-agent hierarchies
- multiple collaboration surfaces

TWO-SPEED AGENT PRINCIPLE
Handoff should have two execution paths, plus one optional sponsor extension:

FAST PATH
For actions where the desired operation is already clear:
- fetch GitHub issue/PR
- assign issue
- request PR reviewer
- send Slack message

Flow:
meeting -> GPT-Live-1 -> Responses reasoning -> narrow tool -> result -> spoken confirmation

DEEP PATH (STRETCH)
For work that genuinely benefits from an autonomous coding/research harness:
- investigate a bug
- inspect a repository
- run tests
- prepare a patch
- produce a technical explanation

Flow:
meeting -> GPT-Live-1 -> delegate task -> Agents API / coding harness -> result later in the same meeting

Do NOT put the Agents API in the realtime critical path for simple actions.

OPTIONAL AIRWALLEX DEMO EXTENSION (STRETCH)
If the Airwallex Developer MCP and sandbox access are already available, Handoff may demonstrate one basic finance action:

User:
"Handoff, create a payment link for that invoice."

Flow:
meeting -> GPT-Live-1 -> Handoff -> Airwallex Developer MCP -> sandbox payment link -> optional Slack delivery -> spoken confirmation

Keep this intentionally tiny. Resolve the invoice and amount from meeting context, create only a sandbox payment link, and optionally send the link through Slack. Do not implement production AgentOS, payments infrastructure, cards, payouts, beneficiaries, or additional Airwallex workflows.

CORE STRATEGIC LINE
"One surface -> contextual understanding -> real side effect -> human-safe action -> visible confirmation."

DEMO SUCCESS CRITERIA
The judges should visibly understand this sequence in seconds:
1. Meeting context exists.
2. User refers to something naturally.
3. Handoff resolves the reference.
4. Handoff chooses a real action.
5. Handoff optionally confirms consequential changes.
6. Handoff performs the side effect.
7. Handoff speaks the result.
8. The activity panel proves what happened.

An optional sponsor extension may additionally show:
9. Handoff resolves an invoice reference.
10. Handoff creates a sandbox payment link through Airwallex Developer MCP.
11. Handoff optionally shares the link through Slack and confirms it verbally.

PROJECT CONCEPT — HANDOFF V2
Last updated: 2026-09-12

ONE-LINE IDEA
Meetings should not end with a list of action items. They should end with the actions already done.

PRODUCT
Handoff is a realtime voice agent that joins a live meeting as a participant, understands the ongoing conversation, resolves contextual references, and performs actions across tools like GitHub and Slack when explicitly invoked. As an optional sponsor extension, it can create one sandbox payment link through the Airwallex Developer MCP.

Handoff is NOT a meeting-transcription product.

PRIMARY USER STORY
During a meeting:

User:
"Handoff, assign that issue to me and send me the details privately on Slack."

Handoff should:
1. Understand "that issue" from the recent meeting context.
2. Resolve "me" to the current user's configured identity.
3. Decide that the request contains two low-latency tool actions.
4. Assign the GitHub issue.
5. Send the Slack DM.
6. Verbally confirm both actions.
7. Publish visible activity events into the meeting UI.

IMPORTANT PRODUCT DIFFERENTIATOR
The value is NOT:
- speech-to-text
- summarization
- generic note taking

The value is:
- continuous meeting context
- references such as "that", "him", "the fix", "what we decided"
- realtime spoken interaction
- natural interruption/correction
- real external side effects
- cross-system action chaining
- lightweight human approval
- visible action provenance
- optional delegation of genuinely complex work

IMPORTANT:
The deep-work path is a stretch capability.
It must NOT delay or destabilize the core realtime demo.

MVP FAST TOOLS
Implement only narrow, deterministic tools:

1. get_github_item(issue_or_pr)
2. assign_github_issue(issue, person)
3. request_pr_review(pr, person)
4. send_slack_message(person_or_channel, message)

Optional:
5. create_github_issue(repo, title, description)

Do not expose dozens of GitHub or Slack operations to the realtime model.

OPTIONAL AIRWALLEX DEMO TOOL — STRETCH
Only if the core demo is stable and the Airwallex Developer MCP sandbox is available:

6. create_airwallex_payment_link(invoice_or_amount)

Demo action:
"Handoff, create a payment link for that invoice."

Handoff should:
- resolve the invoice and amount from meeting context
- call the Airwallex Developer MCP against its sandbox
- receive the generated payment link
- optionally send the link through Slack
- verbally confirm completion and publish the action trace

Do not implement production AgentOS, payments infrastructure, cards, payouts, beneficiaries, or additional Airwallex workflows.

DEEP-WORK TOOLS — STRETCH
Only if the core demo is already stable:

7. start_repo_task(repo, objective, github_context)
8. get_repo_task_status(task_id)

Example use:
"Handoff, investigate why that auth issue is happening."

Handoff can:
- resolve "that auth issue" -> GitHub #12
- acknowledge immediately
- start a deep repository task
- allow the meeting to continue
- show task progress in the activity panel
- report the result later

MEETING STATE
Use a tiny explicit in-memory object for demo reliability.

Example:

meeting_state = {
    "current_github_item": "#12",
    "current_pr": "#18",
    "current_person": "Guru",
    "last_topic": "authentication timeout",
    "pending_action": None
}

Purpose:
- preserve critical references deterministically
- make interruption/correction reliable
- reduce dependence on the model re-inferring important entities every time

This is NOT a database or long-term memory system.

APPROVAL MODEL
Keep approval conversational and lightweight.

READ ACTIONS
Examples:
- get issue
- get PR

Behavior:
- execute immediately

LOW-RISK WRITES
Examples:
- Slack message
- request reviewer

Behavior:
- normally execute immediately for the hackathon demo

CONSEQUENTIAL WRITES
Examples:
- assignment changes
- creating a sandbox payment link
- creating PRs
- merges
- deployments

Behavior:
1. set pending_action
2. Handoff says what it is about to do
3. user says "yes", "go ahead", or corrects it
4. execute only after approval

No approval dashboard is required.

DEMO STORY

SCENE 1 — Retrieve context
User:
"The auth bug is still happening. I think there's already an issue for it."

User:
"Handoff, pull up GitHub issue 12."

Handoff:
"Issue 12 is the authentication timeout bug. It's currently unassigned and marked high priority."

Activity:
CONTEXT
GitHub #12 -> authentication timeout bug

RESULT
✓ GitHub #12 retrieved

SCENE 2 — Resolve contextual reference + perform two actions
User:
"Okay, assign that to me and send me the details privately on Slack."

Handoff:
- resolves "that" -> issue #12
- resolves "me" -> current user
- assigns issue #12
- sends Slack DM
- confirms both

Activity:
CONTEXT
"that" -> GitHub #12
"me" -> Guru

ACTION
Assign GitHub #12 -> Guru
Send Slack DM -> Guru

RESULT
✓ GitHub #12 assigned
✓ Slack DM sent

SCENE 3 — PR workflow
User:
"Actually there's already a fix in PR 18. Request me as a reviewer and let engineering know we're looking at it."

Handoff:
- requests current user as reviewer on PR #18
- posts a message to #engineering
- confirms both

Activity:
✓ Reviewer requested on PR #18
✓ Posted to #engineering

SCENE 4 — Realtime interruption / correction
Handoff begins proposing or confirming an action.

User interrupts:
"Actually, hold on. Don't assign it to Sarah. Assign it to me."

Handoff adapts immediately and updates/cancels the pending action before execution.

This is an important GPT-Live-1 showcase.

SCENE 5 — OPTIONAL DEEP WORK
Only include if stable.

User:
"Handoff, investigate why that auth issue is happening."

Handoff:
"Yep. I'll investigate issue 12. Keep going."

Activity:
DELEGATED TASK
Investigate GitHub #12

AGENT
OpenAI Agents API / coding harness

STATUS
- repository loaded
- searching auth flow
- running tests

Later:
Handoff:
"I finished investigating issue 12. The likely cause is in the token refresh timeout path. I have the findings ready."

SCENE 6 — OPTIONAL AIRWALLEX PAYMENT-LINK WORKFLOW
Only include this sponsor extension if the core demo is stable and sandbox access is ready.

User:
"Handoff, create a payment link for that invoice."

Handoff:
- resolves "that invoice" and the amount from recent meeting context
- calls the Airwallex Developer MCP against the sandbox
- receives a sandbox payment link
- optionally sends the link to the user through Slack
- verbally confirms what it did

Activity:
CONTEXT
"that invoice" -> invoice + amount

Create Airwallex sandbox payment link

RESULT
✓ Payment link created
✓ Slack delivery completed (optional)

It visibly demonstrates:
- realtime voice
- interruption
- contextual reference resolution
- structured meeting state
- GitHub integration
- Slack integration
- real external side effects
- cross-tool execution
- lightweight approval
- visible action trace
- optional long-running agent delegation
- optional extension from developer tooling into a sandbox finance workflow

IMPORTANT PITCH LINE
"Most meeting assistants create notes. Handoff turns decisions into actions while the meeting is still happening."

OPTIONAL TECHNICAL PITCH LINE
"Handoff uses GPT-Live-1 for the live conversation, fast OpenAI reasoning for immediate tool actions, and only delegates to a full agent harness when the work genuinely requires autonomy."

OPTIONAL SPONSOR EXTENSION PITCH
"When the meeting mentions an invoice, Handoff can resolve it from context and create a sandbox payment link through the Airwallex Developer MCP, without turning the MVP into a payments platform."

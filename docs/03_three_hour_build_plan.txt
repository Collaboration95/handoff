MEETING SURFACE
Use a simple browser page.
It represents the meeting.
The microphone streams audio to OpenAI's realtime voice model.
The meeting app should have a small "Agent Activity" panel so judges can see actions.

SLACK STRATEGY — MINIMUM PATH OF RESISTANCE
Slack is an action destination, NOT the place where Relay receives commands.

Do:
- Create/use a free Slack workspace.
- Create one custom Slack app/bot.
- Let the backend use Slack's API to post messages.
- Use one or two channels like #engineering and #product.
- Send DMs to the current user if there are no other real users.

Do NOT:
- Implement Slack mentions/events.
- Implement incoming commands from Slack.
- Depend on Slack Premium.

IF ONLY ONE SLACK ACCOUNT EXISTS
This is fine.

Use a simple contact mapping:
people = {
  "Guru": {
    "github": "<github username>",
    "slack": "<Slack user ID>"
  }
}

For the demo, Relay can send a DM to the same user.
If another hackathon participant joins the free workspace, optionally add them later.

GITHUB STRATEGY
Use a dedicated demo repository containing:
- realistic issues
- at least one open PR
- predictable issue/PR numbers
- user already eligible for assignment/review

Recommended test fixtures:
- Issue #12: authentication timeout bug
- Issue #42: retry / HTTP 429 issue
- PR #18: proposed fix for authentication issue

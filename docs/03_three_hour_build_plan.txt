HANDOFF V2 — 3-HOUR CORE BUILD PLAN
Last updated: 2026-09-12

PRIMARY GOAL
Ship one reliable end-to-end demo:

live meeting
-> GPT-Live-1 conversation
-> contextual reference
-> GitHub action
-> Slack action
-> spoken confirmation
-> visible action trace

The core demo must be stable within ~3 hours.

The hackathon has additional time beyond this personal target, but any remaining time should first improve reliability and only then be used for a deep-work Agents API feature.

NON-NEGOTIABLE ARCHITECTURAL RULE
Do not build solved infrastructure.

Use:
- LiveKit Meet for meeting UI / WebRTC
- LiveKit Agents for the agent participant
- GPT-Live-1 for realtime spoken interaction
- OpenAI Responses-style backend reasoning/tool selection
- direct GitHub API wrappers
- direct Slack API wrappers
- LiveKit data messages for Agent Activity UI events

DO NOT BUILD
- Zoom integration
- Google Meet integration
- Microsoft Teams integration
- custom WebRTC
- custom microphone transport
- custom STT
- custom TTS
- custom interruption system
- meeting recording
- Slack incoming events
- Slack slash commands
- full Slack bot surface
- multiple Slack workspaces
- production OAuth
- speaker diarization
- vector database
- long-term memory
- full contacts system
- Jira
- Linear
- calendar integration
- generic multi-agent framework
- database
- sophisticated approval UI
- large MCP tool surface in the realtime path
- production payments infrastructure, cards, payouts, beneficiaries, or additional Airwallex workflows

CORE SYSTEM

Human(s)
   ->
LiveKit Room
   ->
Handoff Agent participant
   ->
GPT-Live-1
   ->
fast reasoning / narrow tool calls
   -> GitHub
   -> Slack
   ->
spoken confirmation
   +
LiveKit data event
   ->
Agent Activity panel

TINY REQUIRED STATE

meeting_state = {
    "current_github_item": None,
    "current_pr": None,
    "current_person": None,
    "pending_action": None
}

Do not add persistence unless absolutely necessary.

TIMEBOX

0:00 - 0:30
REALTIME FOUNDATION
- fork/start from LiveKit Meet
- create/join test room
- run Handoff as a LiveKit agent participant
- connect GPT-Live-1
- verify:
  - user can speak
  - Handoff can hear
  - Handoff can answer
  - user can interrupt Handoff

Success condition:
A two-way realtime conversation works before anything else is added.

0:30 - 1:10
GITHUB FAST PATH
Implement:
- get_github_item(issue_or_pr)
- assign_github_issue(issue, person)

Use a dedicated demo repository with predictable fixtures:
- Issue #12: authentication timeout bug
- Issue #42: retry / HTTP 429 issue
- PR #18: proposed authentication fix

Add basic meeting_state updates when an issue/PR is retrieved.

Success condition:
"Handoff, pull up issue 12."
Then:
"Assign that to me."
works end-to-end.

1:10 - 1:35
PR + SLACK
Implement:
- request_pr_review(pr, person)
- send_slack_message(person_or_channel, message)

Keep Slack output-only.

Use:
- one free workspace
- #engineering
- optional #product
- current user's DM

Success condition:
"Request me on PR 18 and tell engineering."
causes both real side effects.

1:35 - 2:05
CONTEXT + APPROVAL + INTERRUPTION RELIABILITY
Implement:
- meeting_state
- people identity mapping
- pending_action
- confirmation/correction behavior for consequential actions

Test:
"Assign it to Sarah."
Handoff starts confirmation.
User interrupts:
"Actually, assign it to me."
Handoff updates pending_action before execution.

Success condition:
No accidental execution of the superseded action.

2:05 - 2:25
AGENT ACTIVITY PANEL
Build only a small judge-visible timeline.

Minimum events:
- context_resolved
- action_proposed
- approval_received
- action_started
- action_completed
- action_failed

Example:

CONTEXT
"that" -> GitHub #12

ACTION
Assign #12 -> Guru

RESULT
✓ GitHub #12 assigned

Use LiveKit room/data messaging.
Do not create a second backend transport unless necessary.

2:25 - 3:00
FEATURE FREEZE
Stop adding core features.

Use this time for:
- clean demo state
- repeatable fixture reset
- failure handling
- secrets/config checks
- latency reduction
- exact demo rehearsal
- UI cleanup
- readable action events
- spoken response polish

MUST WORK BEFORE ANY STRETCH FEATURE
1. LiveKit meeting
2. GPT-Live-1 realtime conversation
3. interruption
4. contextual reference resolution
5. GitHub read
6. GitHub write
7. Slack message
8. spoken confirmation
9. Agent Activity panel
10. demo reset/repeatability

STRETCH FEATURE — ONLY AFTER CORE IS STABLE
Add one deep-work task:

start_repo_task(repo, objective, github_context)

Possible implementation:
GPT-Live-1
-> fast reasoning
-> start_repo_task(...)
-> OpenAI Agents API / coding harness
-> repository investigation
-> task progress events
-> result returned to meeting

Example:
"Handoff, investigate why that auth issue is happening."

Do not use this path for:
- assigning an issue
- fetching a PR
- sending a Slack message
- requesting a reviewer

Those remain direct fast tools.

If GPT-6 Astra API access is available:
- use it for the deep coding/repository task
- do NOT put Astra on every realtime voice turn

OPTIONAL AIRWALLEX SANDBOX EXTENSION — ONLY AFTER CORE IS STABLE
Treat this as one small sponsor demo extension, not a new product surface.

Implement only:
- create_airwallex_payment_link(invoice_or_amount)
- resolve the invoice and amount from meeting context
- call the Airwallex Developer MCP against its sandbox
- optionally send the generated link through Slack
- publish the action trace and verbally confirm completion

Demo phrase:
"Handoff, create a payment link for that invoice."

Do not implement production AgentOS, payments infrastructure, cards, payouts, beneficiaries, or any additional Airwallex workflow. If the sandbox MCP is not already ready, cut this feature immediately.

MCP POLICY
Realtime path:
- prefer tiny direct GitHub/Slack functions

Optional partner extension:
- use the Airwallex Developer MCP only for the single sandbox payment-link action
- do not add a broad MCP surface to the realtime path

Deep-work path:
- GitHub MCP may be useful if the agent needs broad repository/issue/PR exploration

Do not spend core implementation time wiring a giant MCP surface.

FALLBACK ORDER IF TIME IS SHORT
Cut first:
1. Airwallex sandbox extension
2. Agents API deep-work feature
3. GitHub MCP
4. create_github_issue
5. multiple contacts
6. fancy Slack formatting
7. sophisticated approval behavior
8. decorative UI

Never cut:
- realtime conversation
- reference resolution
- one GitHub side effect
- one Slack side effect
- spoken confirmation
- visible action trace

FINAL RULE
A boring-looking action that works every time is worth more than a sophisticated agent pipeline that fails on stage.
